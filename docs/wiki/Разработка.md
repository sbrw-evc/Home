# Разработка

## Структура

```
app.py                 сервер: HTTP, опрос источников, SSE, OpenBao, иконки (только стандартная библиотека Python)
static/index.html      SPA: разметка, стили и JS в одном файле, без сборки и зависимостей
Dockerfile             образ на python:3.12-alpine
docker-compose.yml     запуск Home
docker-compose.openbao.yml   подключение к сети OpenBao
openbao/               OpenBao: compose, конфиг, политика, setup.sh, unseal.sh
docs/wiki/             эта документация
.github/workflows/     сборка образа и релиз по тегу
```

## Сервер (`app.py`)

- `ThreadingHTTPServer`, по потоку на запрос; SSE-клиенты ждут на `threading.Condition`.
- Фоновый поток `refresh_loop` опрашивает источники и публикует состояние (`publish`) — с хешем `version`,
  чтобы рассылать только реальные изменения.
- Конфиг пишется атомарно (`config.json.tmp` → `os.replace`).
- Клиент OpenBao — минимальный: KV v2, токен или AppRole с перелогином при `403`.

## Интерфейс (`static/index.html`)

- Маршруты на `location.hash`: `#/`, `#/favorites`, `#/custom`, `#/group/<домен>`, `#/source/<имя>`, `#/settings`.
- Карточки переиспользуются по ключу хоста и перерисовываются только при изменении.
- Свои компоненты без фреймворков: выпадающий список, чекбокс, числовое поле, поле пароля, переключатель,
  модальные окна, уведомления, анимированные счётчики.

## Локальный запуск

```bash
mkdir -p /tmp/home-config
CONFIG=/tmp/home-config/config.json NPM_DB=/path/to/database.sqlite ADMIN_PASSWORD=dev python3 app.py
# http://localhost:8088
```

Или в Docker: `docker compose up -d --build`.

## Релиз

1. Добавьте заметки `.github/release-notes/vX.Y.Z.md`.
2. Создайте и отправьте тег:

   ```bash
   git tag -a vX.Y.Z -m "Home vX.Y.Z" && git push origin vX.Y.Z
   ```

3. Workflow **Release** соберёт образ `ghcr.io/sbrw-evc/home` (amd64 + arm64) с тегами `X.Y.Z`, `X.Y`, `latest`
   и создаст релиз с архивом `home-X.Y.Z-deploy.tar.gz` и `SHA256SUMS`.
