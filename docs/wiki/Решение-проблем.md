# Решение проблем

## Диагностика

```bash
docker logs home                         # версия, адрес OpenBao, ошибки
curl -s localhost:8088/health            # ok <версия>
curl -s localhost:8088/api/state | python3 -m json.tool | grep -A6 '"sources"'
```

Статус каждого источника и ошибка подключения видны в **Настройки → Источники NPM**, а ошибки источников — в точке статуса внизу меню.

## Частые проблемы

**Нет карточек из локального NPM.**
Проверьте `NPM_DATA_DIR` в `.env`: внутри контейнера должен быть файл `/npm/database.sqlite`
(`docker exec home ls -l /npm`). NPM с MySQL/MariaDB подключайте через API.

**Удалённый NPM: `HTTP 400: Invalid email or password`.**
Неверные логин или пароль. Пароль хранится в OpenBao — введите его заново и сохраните.

**Удалённый NPM: `нет соединения`, `certificate verify failed`.**
Адрес недоступен из контейнера или сертификат самоподписанный — снимите «Проверять TLS-сертификат».

**`OpenBao недоступен`, `OpenBao HTTP 503: Vault is sealed`.**
OpenBao запечатан после перезапуска: `./openbao/unseal.sh`.

**`OpenBao не настроен`.**
Не заданы `BAO_ADDR` и `BAO_TOKEN` или `BAO_ROLE_ID`/`BAO_SECRET_ID`. Без OpenBao удалённые NPM добавить нельзя.

**Не открываются настройки: «Нужен пароль администратора».**
Пароль: `bao kv get -field=password secret/npm-dashboard/admin`. Сброс — см. [[Безопасность]].

**Страница не обновляется на лету за прокси.**
Прокси буферизует `/api/events`. Для nginx/NPM приложение само отправляет `X-Accel-Buffering: no`;
для других прокси отключите буферизацию для этого пути. Если поток недоступен, страница всё равно обновляется опросом раз в 5 секунд.

**У сайта нет иконки.**
Сайт не отвечает с сервера ни по публичному адресу, ни через бэкенд, или иконки у него нет (например, у API-сервисов).
Неудачный поиск повторяется через час. Сбросить кэш: удалите `config/icons` и перезапустите контейнер.
Для своего сайта можно указать адрес иконки вручную.
